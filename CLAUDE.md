# CLAUDE.md — правила работы с этим репозиторием

## Что это

VIP CRM: настольное окно для менеджера VIP-клиентов. Три части:

- **Фронтенд** — `index.html`, `tokens.css`, `main.css`, `reactivation-v30.css`, `main.js`.
  Ванильный JS в одном IIFE, без сборки, без npm, без тестов. Работает в окне Edge/Chrome
  в режиме `--app`.
- **Мост** — `crm_server.ps1` (PowerShell 5.1), запускается через `START_CRM.bat` →
  `START_CRM_HIDDEN.vbs`. Отдаёт статику на `127.0.0.1:8765` и проксирует `/being-api` в
  Google Apps Script, подставляя ключ из `being_config.json` (файла нет в репозитории).
- **Бэкенд** — `Code.gs`, Google Apps Script Web App над Google Sheet (листы Being, 365,
  `since …`).

Журнал изменений и описание версий — `README_START_HERE.txt` (сверху новые).

## Индексные файлы: читать ИХ, а не весь код

Код большой (main.js ≈7 тыс. строк, CSS ≈14 тыс., Code.gs ≈4 тыс.). Чтобы не перечитывать
его целиком, в `docs/code-index/` лежат индексы:

| Файл | Что описывает |
|---|---|
| `docs/code-index/README.md` | Архитектура, потоки данных, «с чего начать» по типовым задачам, процедура обновления индексов |
| `docs/code-index/main.js.md` | Структура main.js, схема `state` и `dom`, все функции по группам, API-контракт, обработчики событий, режимы |
| `docs/code-index/index.html.md` | Разметка: секции экранов, модалки, все id и кто их использует |
| `docs/code-index/css.md` | Токены, структура двух CSS-файлов, карта компонентов → правила, слой `[data-theme="dark"]`, известные долги |
| `docs/code-index/Code.gs.md` | Диспетчер action'ов с форматами ответов, схема листов, кэши, локи, функции по группам |
| `docs/code-index/server.md` | Мост, скрипты запуска, маршруты `/being-api` и `/crm-control` |

Порядок работы над любой задачей:

1. Открыть `docs/code-index/README.md` и индекс нужного файла. Найти функцию, поле state,
   класс или action, который относится к задаче.
2. Читать код **точечно**: `grep -n "<идентификатор>" main.js`, затем `sed -n 'A,Bp'`
   (или Read с offset/limit) только нужного диапазона. Номера строк в индексах
   ориентировочные, точное место всегда ищется grep-ом по имени.
3. Целиком файл читать только если задача действительно этого требует (например,
   массовый рефакторинг) — и тогда обновить индекс так, чтобы в следующий раз не пришлось.

## После любого изменения кода — обновить индексы

Это обязательная часть задачи, а не опция. Изменил код → в том же коммите поправь
соответствующий индекс:

- добавил/удалил/переименовал функцию, поле `state`, handle в `dom`, id в разметке,
  класс в CSS, action в Code.gs → внести в таблицу соответствующего индекса;
- изменил формат запроса/ответа между main.js и Code.gs → обновить API-таблицы
  в `main.js.md` **и** `Code.gs.md`;
- сдвинулись диапазоны строк больше чем на ~50 → обновить колонку «Строки» затронутых
  секций (для остального достаточно, что имена верны);
- изменил поток данных, режим или намеренное решение → обновить README индекса.

Признак хорошего индекса: следующая сессия находит нужное место одним grep-ом.

## Проверка перед коммитом

- `node --check main.js` и `cp Code.gs /tmp/c.js && node --check /tmp/c.js` — синтаксис.
- Для правок CSS/разметки/рендера — визуальный дифф: `tools/visual-check/README.md`
  (мок-сервер + Playwright-скриншоты 16 экранов + попиксельное сравнение). Для чистки
  и рефакторинга ожидается 0.000% отличий на всех экранах.
- Для правок main.js — прогнать сценарии через тот же мок: сохранение заметки из
  Being-карточки, Email/Call в Reactivation, смена даты, поиск. В `console.log`
  стенда не должно быть `pageerror`.
- Code.gs здесь не запускается; изменения должны быть очевидно эквивалентными,
  или проверены в песочнике со стабами `SpreadsheetApp` (см. подход в `Code.gs.md`).

## Соглашения

- Комментарии в коде — по-английски, в стиле существующих (объясняют «почему»).
  Общение с владельцем — по-русски.
- `crm_server.ps1` — UTF-8 с BOM, переводы строк LF. Не терять BOM при правке.
- Версия приложения: `APP_VERSION` в main.js, `?v=` у четырёх подключений в index.html,
  `#localVersion` в index.html, запись в `README_START_HERE.txt`. Версия API Apps Script:
  `version` в `doGet` (`ping`) и `requiredVersion` в main.js.
- Намеренно оставлено, не удалять как «мёртвое»: `getReactivationOffer` в main.js
  (шаблон оффера на будущее, см. комментарий над ней), кнопка `#themeToggle`
  (держит место в доке), `debugSchema`/`debug365`/`clear365Cache` в Code.gs (ручная
  диагностика через `DIAGNOSE_CRM.bat`/curl), режим `file://` с тестовыми данными
  («Open CRM Anyway») в main.js.
- `being_config.json` никогда не коммитить и не читать в ответ пользователю целиком:
  в нём URL деплоя и API-ключ.
